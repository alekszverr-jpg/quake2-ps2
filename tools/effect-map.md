# Flowing-surface test room

Select **Game -> test map -> ps2flow - renderer effects test**, then load the
map. Console alternative: `map ps2flow`. Alpha.92 expands the Alpha.91 room.

The spawn faces three labelled panels:

| Label | Expected behaviour |
| --- | --- |
| STATIC (left) | Vertical stripes stay still. |
| OPAQUE (centre) | Same stripes scroll horizontally; surface is opaque. |
| GLASS (right) | Stripes scroll; stationary grid behind remains visible. |
| DOOR (right wall) | Approach the striped shield to move it along the wall; texture keeps scrolling while the inline brush moves and returns. |

Observe the centre and right samples from different angles and close to the
camera. Watch for cracks, sudden texture-coordinate jumps, or differences
between clipped and unclipped triangles. Shoot the opaque sample with the
blaster to also exercise dynamic-light subdivision with scrolling coordinates.
The room contains no monsters and no water/SURF_WARP surfaces.

Turn around to see four new labelled samples on the opposite wall:

| Label | Expected behaviour |
| --- | --- |
| MODEL | Solid animated checker cube; the wall behind is hidden. |
| ALPHA | Same cube, translucent: wall grid remains visible through it. |
| SPRITE | Animated coloured disc facing the camera; border and centre hole are fully cut out, without a rectangular background. |
| FADE | Two overlapping translucent discs: both should contribute, with the wall visible through them. |

Walk around the low foreground bars: they must cover the lower parts of the
samples when in front. Move close to a disc and turn the camera: crossing the
near plane should clip it smoothly instead of making an entire triangle pop
away. The 96x80 NPOT discs must keep the right shape and have no repeated or
uninitialised texture strips. Animation alternates two frames on server ticks.
MD2 uses ordinary world lighting; sprite colours are unlit as in ref_gl.
The fixture's RF_TRANSLUCENT flag uses the stock client's 0.7 entity alpha;
a closed cube has several overlapping faces, so its combined opacity is higher.

The diagnostic misc_ps2sample spawn is restricted to ps2flow. It transmits
ordinary model indices, frames and render flags through the normal server/client
path; it does not inject client-side test graphics. Campaign entities are unchanged.

Run **benchmark (3 runs)** with the same video/settings as the preceding build
and save both FPS and renderer-details pages. Loading remains excluded; compare
all three passes. This benchmark does not validate the new fixture visually.

Alpha.93 adds **Game -> world lights compare (6 runs)**. This runs demo1
three times with world dynamic lights ON, then three times OFF, with the same
frame range and other benchmark settings. The summary shows FPS, frame time,
world render time and ON minus OFF frame milliseconds. Left/Right cycles the
summary, ON runs, OFF runs, ON details and OFF details. Entity illumination,
animated light styles and ordinary transparency remain enabled in both modes.
The original world-light setting is restored after completion or cancellation.
An incomplete run or differing demo-frame ranges cannot establish a cost.
Use this comparison to choose an optimization; it is not itself a speedup.

The geometry, ten WAL textures and diagnostic MD2/SP2/TGA files are original procedural assets
generated by [effect_map.py](effect_map.py), under the repository's GPL v2
licence. No commercial game assets are included. Compilation uses
[yquake2/maptools](https://github.com/yquake2/maptools) at commit
`9b7e43334646f63f25a7aebfd62070b3aebc2554`, derived from the GPL Quake II tools.
`prepare_maptools.py` fixes QRAD's pointer alignment cast from `int` to
`uintptr_t`: the original truncates the address and crashes on a 64-bit host.
CI runs QBSP, QVIS and QRAD, then checks BSP38 structure, actual face flags,
visibility, lightmaps, player hull spawn clearance and the inline door model.

To rebuild on Linux, generate into a directory containing the exact path
`quake2/baseq2` (required by the compiler's game-directory inference):

```sh
python3 tools/effect_map.py build/effect-map/quake2/baseq2
python3 tools/prepare_maptools.py build/effect-map-tools
make -C build/effect-map-tools -j2 release/qbsp3 release/qvis3 release/qrad3 CFLAGS="-O2 -fcommon -fno-strict-aliasing -Wall -MMD"
build/effect-map-tools/release/qbsp3 -leaktest "$PWD/build/effect-map/quake2/baseq2/maps/ps2flow.map"
build/effect-map-tools/release/qvis3 "$PWD/build/effect-map/quake2/baseq2/maps/ps2flow.bsp"
build/effect-map-tools/release/qrad3 -threads 1 -bounce 0 -ambient 0.2 "$PWD/build/effect-map/quake2/baseq2/maps/ps2flow.bsp"
python3 tools/effect_map.py build/effect-map/quake2/baseq2 --verify
```

Download the CI `ps2flow-test-map` artifact. Copy its `maps/ps2flow.bsp`,
`textures/ps2test/*.wal`, `models/ps2test/*` and `sprites/ps2test/*` into the
matching directories inside `baseq2`, alongside the Alpha.92 PROFILE ELF.
The `.map` source is optional at runtime. **Do not install the generated
compiler-only `pics/colormap.pcx`**: runtime must retain the game's palette.
The artifact intentionally excludes it. Other maps and PAK files are unchanged.

For detailed light CPU work, use **Game -> world lights profile (6 runs)**
(Alpha.95). Left/Right cycles the existing five pages, then **Light profile ON**
and **Light profile OFF**. Send these last two pages. This mode adds timers and
perturbs FPS; use ordinary **world lights compare** to measure optimization gains.
Both modes restore the caller's world-light and diagnostic settings.

Profile units are averages per measured frame. Select ms includes surface-plane
and triangle-AABB tests. Split ms includes edge selection, midpoint interpolation
and midpoint clip distances, excluding recursive children and triangle submission.
Alpha.96 Color ms covers cache-miss dynamic colour calculation and excludes
lookup. Color hits/Color misses count reuse/recomputation; Lit vertices counts
all emitted requests, Vertex tests counts only recomputed vertex/light pairs. Other rows count
surface calls, plane/light pairs, AABB calls, AABB/light pairs, rejected pairs,
recursive nodes, actual splits, lit emitted vertices and vertex/light pairs.
Inline BSP brushes are included; alias-model illumination is excluded. Bounds
counts include original source triangles and transient children. Rejected is
per candidate light, so it can exceed Bounds calls. These are subsets of world
and brush entity phases, not additional frame costs.
